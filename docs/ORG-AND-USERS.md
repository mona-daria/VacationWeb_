# Оргструктура, сотрудники, пароли

Первый кадровик создается командой node --env-file=.env server/admin.mjs из BOOTSTRAP_* в .env. При первом входе требуется сменить временный пароль, затем войти заново.
В интерфейсе кадровика откройте раздел сотрудников:
1. Создайте руководителей (роль manager).
2. Создайте директора (director) и дополнительных кадровиков (hr), если нужны.
3. Создайте сотрудников (employee): ФИО, уникальный латинский логин, одинаковое написание подразделения, назначенный руководитель, индивидуальный временный пароль 12–128 символов.
4. Передайте каждому его ссылку, логин и пароль по принятому защищенному каналу. Программа не отправляет письма автоматически.
5. Сотрудник меняет временный пароль при первом входе. Кадровик не видит новый пароль.

Одна учетная запись имеет одну роль и максимум одного назначенного руководителя. Самосогласование запрещено.
Руководитель может подавать собственные даты только при наличии назначенного ему другого руководителя. Обязательность подачи перед согласованием кадровиком проверяется для всех активных пользователей роли employee; другие роли не считаются обязательными участниками.
Подразделение — текстовая метка, а не иерархический справочник. Подготовьте единое написание подразделений заранее.
Массовый импорт, редактирование/блокировка сотрудников через интерфейс, совмещение ролей, дерево подразделений, AD/LDAP и почтовая рассылка не реализованы. Если нужны, это отдельные доработки. Не создавайте дубль учетной записи для изменения руководителя — разработчик должен реализовать контролируемое изменение с проверкой согласований.

## Сброс забытого пароля
Администратор сервера задает RESET_LOGIN и RESET_PASSWORD в .env и выполняет node --env-file=.env server/reset-password.mjs.
Затем удаляет RESET_PASSWORD из .env и передает новый временный пароль сотруднику. Все сессии пользователя закрываются, следующий вход требует смены пароля.
Не храните таблицу постоянных паролей, не записывайте открытые пароли в БД.

## Маршрут согласования
Сотрудник подает периоды → назначенный руководитель согласует → кадровик видит полный свод и все пересечения.
Кадровик возвращает заявку с комментарием либо принимает допустимое пересечение с объяснением. Принятое пересечение остается в общем списке.
После возврата сотрудник меняет даты и повторно отправляет руководителю.
Когда все обязательные сотрудники подали даты, все заявки согласованы и по всем пересечениям есть решения, кадровик передает план директору.
Директор утверждает либо возвращает план. После утверждения редактирование закрыто, кадровик может открыть новую редакцию с комментарием; прежние снимки доступны в Excel.
