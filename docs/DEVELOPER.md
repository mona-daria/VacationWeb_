# Руководство разработчика

Стек и точные версии — README и package-lock.json. Исходники являются исполняемым кодом: генерации или минификации нет. Открывать VacationWeb.sln в VS2019 либо папку в другом редакторе.

## Куда смотреть при изменениях
- Тексты/формы: public/app.js. mine — ввод дат; calendar — сводный календарь; requests — согласование заявок; overlapPage — пересечения; approval — план; people — создание пользователей; history — история.
- Навигация/фильтры: render, page, filters и обработчики click/change.
- Оформление: styles.css. Пользовательские значения выводите только через esc, не вставляйте непроверенные строки в innerHTML.
- Правила периода: validatePeriods в domain.mjs. Изменения продублируйте понятной подсказкой в интерфейсе; окончательная проверка всегда серверная.
- Пересечения: conflicts в domain.mjs. Сравниваются все периоды согласованных руководителями заявок, в том числе между подразделениями. Границы включительны. Решения кадровика не скрывают пересечения; фильтр «неурегулированные» может скрывать только решенные в текущем представлении.
- Согласования и права: submit, requestAction, conflictAction, planAction в service.mjs.
- Excel: workbook в export.mjs.
- Новый API: http.mjs (маршрут), service.mjs (проверки/транзакция), app.js (форма), тесты.
- Изменение схемы: отдельная миграция с резервной копией. CREATE TABLE IF NOT EXISTS не добавляет колонку в существующую таблицу.

## Как проходит запрос
Форма → api() → HTTP JSON + cookie + CSRF → проверка сессии/роли → транзакция service → параметризованный SQL → PostgreSQL → JSON → обновление экрана.
Не переносите пароль БД в public: браузеры пользователей общаются только с сервером приложения.

## Согласованность данных
lockPlan блокирует строку года через SELECT FOR UPDATE. Изменения плана и заявок одного года последовательны.
Заявки имеют version, план — revision; устаревшее действие возвращает 409.
Решение по пересечению привязано к версиям заявок. После изменения дат старое решение не применяется.
Снимки plan_snapshots сохраняют состав и согласования на момент действия; последующие изменения не переписывают снимки.
Снимки неизменяемы через API, но не защищены от администратора БД.
Аудит в интерфейсе ограничен последними 500 событиями выбранного года.

## Пароли и ограничения
scrypt с солью, токены сессий хранятся хешами, сессия 8 часов. Смена/сброс пароля закрывает сессии.
Лимит неудачных входов хранится в памяти процесса: 10 на логин и 100 на адрес за 15 минут. За обратным прокси адрес общий; для промышленной нагрузки настройте дополнительный лимит на прокси с корректной доверенной цепочкой адресов. Горизонтальное масштабирование лимитера не реализовано.
Подсчет пересечений попарный; нагрузочное тестирование на вашем объеме обязательно.

## Построчный просмотр
Откройте CODE-MAP.html: полный текст основных исходников с номерами строк и краткими пояснениями типов операций. Сложные бизнес-правила объяснены выше и в API.md; автоматические пояснения строк являются навигацией, а не формальной спецификацией JavaScript.
После правок выполните node --test --test-concurrency=1 tests/*.test.mjs и сценарий ACCEPTANCE.md. Обновите документацию. Исходники правьте в исходных файлах, не в HTML-карте.
